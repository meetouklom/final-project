# DormFix

DormFix เป็นเว็บแอปสำหรับแจ้งซ่อมและติดตามงานภายในหอพัก รองรับทั้งภาษาไทยและ
ภาษาอังกฤษ ผู้พักอาศัยสามารถแจ้งปัญหา ติดตามสถานะ และรับการแจ้งเตือน
ส่วนผู้ดูแลสามารถจัดการคำขอและส่งลิงก์ตั้งรหัสผ่านใหม่ให้ผู้พักอาศัยทางอีเมลได้

## เทคโนโลยีที่ใช้

- Python 3.10 ขึ้นไป
- Django 5.2
- Django REST Framework
- SQLite สำหรับพัฒนาในเครื่องและการติดตั้งใช้งานเบื้องต้น

## เริ่มต้นใช้งาน

เปิด PowerShell ในโฟลเดอร์โปรเจกต์ แล้วรันคำสั่งต่อไปนี้:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

เปิดเว็บที่ <http://127.0.0.1:8000/> หากต้องการเข้าหน้าจัดการระบบ
ให้สร้างบัญชีผู้ดูแลด้วยคำสั่ง:

```powershell
python manage.py createsuperuser
```

สำหรับ macOS หรือ Linux ให้สร้างและเปิดใช้งาน virtual environment ด้วยคำสั่ง:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

จากนั้นใช้คำสั่งติดตั้งแพ็กเกจและเตรียมระบบเดียวกับขั้นตอน PowerShell ด้านบน

### อีเมลสำหรับพัฒนา

เมื่อ `DEBUG=True` Django จะแสดงอีเมลและลิงก์ตั้งรหัสผ่านใหม่ในเทอร์มินัล
ที่ใช้เปิดเซิร์ฟเวอร์ จึงไม่จำเป็นต้องตั้งค่า SMTP เพื่อทดลองในเครื่อง

### ผู้ช่วย AI วิเคราะห์คำร้อง

DormFix รองรับ Ollama สำหรับช่วยผู้ดูแลสรุปคำร้องเป็นภาษาไทยและอังกฤษ แนะนำหมวดหมู่
และประเมินความเร่งด่วนจากปุ่ม “AI Analyze” ในแต่ละแถวบน Dashboard หรือจากหน้ารายละเอียด
คำแนะนำจะไม่เปลี่ยนข้อมูลคำร้องโดยอัตโนมัติ
และต้องให้ผู้ดูแลตรวจสอบก่อนใช้งาน ข้อความคำร้องจะถูกประมวลผลในเครื่องผ่าน Ollama
โดยส่งเฉพาะหัวข้อ หมวดหมู่ และรายละเอียด ไม่ส่งชื่อผู้แจ้งหรือสถานที่

ติดตั้ง Ollama จาก <https://ollama.com/download> แล้วดาวน์โหลดโมเดลที่ตั้งค่าเริ่มต้น:

```powershell
ollama pull qwen2.5:3b
```

เปิด Ollama ให้ทำงานอยู่ จากนั้นเปิดแอปตามขั้นตอนปกติ ผู้ดูแลจะเห็นปุ่ม
“AI Analyze” ในแต่ละแถวของ Dashboard และปุ่มวิเคราะห์ในหน้ารายละเอียดคำร้อง
หากติดตั้ง Ollama หรือโมเดลไว้ตำแหน่งอื่น
สามารถกำหนด `OLLAMA_BASE_URL` และ `OLLAMA_MODEL` เป็น environment variables ได้
ไม่จำเป็นต้องมี API key หรือส่งข้อมูลไปยังบริการ AI ภายนอก

ก่อนนำขึ้นใช้งานจริง ให้ตั้งค่า SMTP ตาม
[คู่มือติดตั้งบน PythonAnywhere](docs/deployment/PYTHONANYWHERE.md)

## แผนผังโปรเจกต์

| Path | Responsibility |
| --- | --- |
| `accounts/` | บัญชีผู้ใช้ การเข้าสู่ระบบ บทบาท และแดชบอร์ด |
| `repairs/` | งานแจ้งซ่อม ความคิดเห็น คะแนน การแจ้งเตือน และ API |
| `dormrepair/` | การตั้งค่า Django เส้นทางหลัก และ WSGI |
| `templates/` | โครงหน้าและเทมเพลต HTML |
| `static/css/` | ไฟล์รูปแบบหน้าจอ |
| `docs/` | เอกสารโครงสร้างและคู่มือติดตั้ง |
| `manage.py` | เครื่องมือสั่งงาน Django |
| `requirements.txt` | รายการแพ็กเกจ Python ที่โปรเจกต์ใช้ |

ดูหน้าที่ของไฟล์และภาพรวมการทำงานได้ที่
[คู่มือโครงสร้างโปรเจกต์](docs/PROJECT_STRUCTURE.md)

## ข้อมูลและความปลอดภัย

- ระบบเก็บรหัสผ่านด้วยการแฮชของ Django และจะไม่แสดงรหัสผ่านเดิมของผู้ใช้
- การสมัครทั่วไปสร้างได้เฉพาะบัญชีผู้พักอาศัย
  ผู้ดูแลจัดการบทบาทและเปิด/ปิดบัญชีได้จากหน้า “จัดการบัญชี”
  ระบบเก็บประวัติผู้ดำเนินการและการเปลี่ยนแปลงบัญชีไว้ตรวจสอบย้อนหลัง
  ก่อนปิดใช้งานจะแสดงการยืนยัน และบัญชีกับประวัติแจ้งซ่อมจะไม่ถูกลบ
  ส่วนการสร้างหรือกำหนดผู้ดูแลระบบ Django ให้ทำผ่าน Django Admin
- ห้ามนำ `DJANGO_SECRET_KEY`, ข้อมูล SMTP, ฐานข้อมูลในเครื่อง
  หรือไฟล์ที่ผู้ใช้อัปโหลดขึ้นระบบควบคุมเวอร์ชัน
- `.gitignore` ยกเว้นฐานข้อมูล (`db.sqlite3`), ไฟล์อัปโหลด (`media/`),
  virtual environment, cache และไฟล์ static ที่สร้างขึ้น
  ควรสำรองฐานข้อมูลและไฟล์อัปโหลดก่อนย้ายหรือติดตั้งโปรเจกต์
